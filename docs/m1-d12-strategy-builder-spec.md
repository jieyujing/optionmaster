## Problem Statement

## Solution

以 Strategy Builder 为默认研究入口：左侧多品种、日期、交割月 T 型链；右侧组合持仓、净成本、当前/情景/到期三线图、收益风险与 Greeks。直接编辑 signed quantity，建仓价可覆盖，支持一至八个期权腿及已验证的对应期货/现货腿；跨交割月保留，跨日显式保成本重估。当前历史归档是开发/回归真实 fixture，最终发布必须接入通过独立准入的 ClickHouse 最新完整交易日及历史日期；不得将仅归档版本称为完成。原有压力测试保留为高级分析，旧 API 和旧入口兼容。三个工作流共享先冻结的契约、并行推进；完整集成后一次性交付，非三次生产发布。

2. As an options researcher, I want to filter by verified exchange and product, so that unsupported coverage is explicit.

4. As an options researcher, I want to choose a supported historical trading day, so that I can replay historical strategy construction.
5. As an options researcher, I want to switch delivery months and locate ATM strikes, so that I can construct calendar and diagonal spreads efficiently.
6. As an options researcher, I want calls and puts aligned by exact strike with separate contract/expiry identities and marks, so that neither missing side nor mismatched terms are mistaken for a quote.
7. As an options researcher, I want to inspect settlement/approved close basis, IV availability and optional Greeks, so that displayed quote fields are traceable and never synthetic.
8. As an options researcher, I want to edit signed quantity directly via +/- and keyboard input, so that buys, sells and ratios use one interaction.
9. As an options researcher, I want zero quantity to remove a leg and the same contract to update its net quantity, so that duplicates cannot create inconsistent exposure.
10. As an options researcher, I want all selected legs visible and highlighted across month tabs, so that changing month never silently changes my strategy.
11. As an options researcher, I want one to eight option legs, so that a single call/put and a multi-leg structure both work.

32. As an options researcher, I want date switching to offer rebuild versus keep-entry revaluation, so that original costs are not silently replaced.

34. As an options researcher, I want explicit confirmation before replacing a portfolio when switching product, so that unsaved selections are not lost.

### 3. Portfolio and time/state invariants (Q1–Q4/Q10/Q13/Q14)

Strategy Portfolio contains exact option identity and optional exact Underlying Leg identity, signed nonzero quantity, quote-unit entry price, entry trade date, source provenance, multiplier and instrument class, tied to one family/exchange/asset class. UI zero removes; invalid intermediate text is draft state, not sent for valuation. Max eight distinct option legs, min one for option analysis; retain existing strict signed integer option quantity |q|<=1000 until explicitly changed. Require at most one net underlying position per exact referenced deliverable; no unrelated products, spot proxy or continuous futures; underlying quantity is verified native contracts for futures or explicit supported native spot units, never arbitrary assumed lot. Propose finite configured caps for underlying count/quantity at T01, no release until selected. Underlying-only and empty draft clear option expiry analysis, no invented horizon; same contract may be netted, conflicting entry-price histories require explicit edited net average, no fill ledger. Entry Price is a finite nonnegative quote price for option and a valid price in the verified underlying domain; explicit zero premium allowed if admitted data and entry policy allow; no negative premium. Existing quotes retain source basis; edits affect cash accounting only. Futures notional is not a premium debit or margin; spot acquisition cost kept separate. No fee, tax, execution, margin or financing model; clearly label gross theoretical P&L excluding these.

State: disconnected → loading snapshot → ready → draft revision → payoff/model pending or valid/unavailable per capability. A change to quantity/entry price, date, provider, scenario, shocks, axes or horizon invalidates dependent results via monotonic portfolio revision and server-correlated input hash. Month tab/filter change alone is not economic change. Switching product confirms and clears; switching date explicitly rebuilds (new entry snapshot) or revalues (retain original entry date, costs, quantities, stable exact native contract). Revalidate terms/version on new date using reviewed mappings; reject invalid, absent, changed/expired identities visibly without discarding. Proposed conservative boundary: revaluation trade date cannot precede entry trade date and must be before all selected expiry dates; earlier research uses rebuild. Single consistent Valuation Snapshot for all legs; no mixing entry-date mark with new valuation IV. Do not persist credentials or positions externally; multi-portfolio storage not part of first release.

Horizon semantics: for legacy pre-expiry model curves, follow existing exclusive cutoff/date guard and ACT/365F. Strategy terminal payoff uses explicit hypothetical terminal value of the option, no real exercise. For common actual expiry (verified same cutoff or date-only terminal convention for same expiry date), all option legs expire at horizon; for cross-expiry earliest expiry, only legs expiring at that boundary get intrinsic payoff. Far legs need verified remaining positive time and policy. A date-only expiry cannot prove actual intraday cutoff; exact timestamp where verified, otherwise terminal date is a hypothetical boundary. Far-leg valuation on a date-only horizon needs an explicitly reviewed nominal time convention (proposed reuse D05 nominal Beijing 15:00 only where verified compatible; no generic assumed exchange cutoff), otherwise conditional model curve UNAVAILABLE. If two options share a calendar date but known different cutoffs, do not misclassify as identical expiry; use verified earliest cutoff or reject ambiguous mixing. Never send T=0 to a positive-time IV solver; no post-first-expiry original portfolio valuation; no actual cash settlement, assignment, futures conversion or exercise path. American terminal intrinsic is conditional on holding until that horizon, not early-exercise strategy. Rates use verified dated policy, not future information. Model scenario time cannot precede current valuation clock; at the first-expiry boundary delegate to the terminal/horizon calculation, not legacy time engine.

### 4. Mathematical contract (Q1/Q2/Q4/Q6/Q7/Q8/Q12/Q14)

Let q be signed position, M verified monetary multiplier per native unit, K strike, c=+1 call/-1 put, e entry premium, F0 the admitted per-underlying reference price, F scenario price, U0 underlying entry price. Monetary option P&L_i = q_i M_i [V_i(F,t,σ,r)-e_i]. At that leg's terminal boundary V_i=max(c_i(F-K_i),0), undiscounted intrinsic. Linear underlying P&L_j=q_j M_j(F_j-U0_j). For spot, native unit conversion is validated; futures variation margin and spot cost accounting are not separately modeled. Sum only compatible currency and units (CNY for initial scope); contributions must reconcile with total; unavailable leg makes aggregate for that specific curve/point/metric UNAVAILABLE (null, reason, no partial sum presented as total). Net Premium=Σ option qMe (positive debit, negative credit). At x=0 and no scenario override current theoretical curve should reconcile with market baseline within existing IV repricing tolerance where identifiable; entry P&L need not be zero after revaluation/custom price.

x is common decimal price return. Per current M0 semantics configured shock u_j is explicit per-underlying override replacing global configured shock if present; evaluated point F_j=F0_j*(1+u_j+x), additive vs original, not compound. Current curve uses u_j=0, base IV and snapshot clock; scenario and first-expiry conditional curve use configured u_j. Single exact underlying display absolute price axis only when mapping is one-to-one and honest across curves; otherwise common percentage axis, reference-price secondary ticks labeled unadjusted F0*(1+x), tooltip each actual F_j and override. Reference underlying explicit, stable and selected; changing it never mutates positions. Price domain checked per underlying: do not assume all futures can never be negative; for current positive-price model require F>0 and proven/admitted declared domain, for exact payoff endpoints handle F=0 only where domain supports it. Define analytic unbounded/finite claims over declared domain and label that domain; do not extrapolate unsupported negative-price model. If any necessary domain or mapping is unknown, mark global risk unavailable, not pretend finite. Breakpoints derive from F_j=K_i (x=K_i/F0_j-1-u_j), domain endpoints and linear tail slopes; solve exact affine roots per segment, including coincident/flat zero intervals, no-grid root guessing. For single underlying, analytic extrema/breakeven over verified domain; multiple underlyings with common shock use analytic conditional one-dimensional payoff, explicitly conditional, not global independent-moves bound. For curves with remaining model-valued legs, report only tested range extrema and numerical crossing intervals (label conditional, non-exhaustive if not proven); do not claim global risk or all roots for arbitrary nonlinear functions. Tail slope determines unbounded profit/loss where domain extends; handle zero tail slope, no roots, identically zero, no finite loss, all-loss/ all-profit, undefined risk/reward ratios, no division by zero or JSON Infinity. Report monetary max loss magnitude with explicit sign convention, profit max and loss max floored at zero for display; separate actual extrema if needed and metric status/reason. Ratio only if both finite and max loss >0; never cap infinite risk.

IV Sticky Strike: base sigma per exact option from admitted mark at current reference time, locked for curves; no recalibration on entry price, qty or shocked price. Configured absolute IV shift per expiry replaces global shift if present; optional additional grid shock adds. Use decimal volatility units, UI pp; finite sigma>0 for remaining model legs, never substitute 0 or fabricate IV. Current line at snapshot clock, configured scenario line at selected pre-expiry time, terminal line same-expiry exact or earliest-expiry conditional (remaining legs model-valued); distinguish legend/time/assumptions. Terminal exact payoff unaffected by IV/rate; horizon line depends on far-leg IV. Model Greeks from verified research model for current/configured pre-expiry states, units M0 (annual calendar Theta; Vega per 1.0 sigma, optionally display per pp with explicit conversion). Group Delta/Gamma by exact underlying; underlying linear Delta qM in quote sensitivity, Gamma/Theta/Vega zero for the modeled linear P&L only. No Greeks for expired option or unavailable model. Do not sum unlike quote/currency units. Keep D11 128 steps and scalar parity, existing rate/IV/Greeks tolerances; new deterministic payoff tests use independently computed monetary golden values at T07 1e-8 absolute where representable, specify rounding for displayed prices/currency, test floating conditioning and root brackets independently without loosening previous tests.
